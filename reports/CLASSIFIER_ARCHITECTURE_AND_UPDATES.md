## 📑 Executive Summary

This report documents the design, implementation, and empirical verification of the **Classifier Module** (`classifier/`) built for the Amazon ML Challenge 2026 Business Entity Resolution project.

The classifier operates downstream of candidate blocking and pairwise feature extraction. It ingests numerical similarity features comparing reference Source 1 (`S1`) entities against candidate records from Source 2 (`S2`) and Source 3 (`S3`), trains a LightGBM tabular gradient boosting model, optimizes decision thresholds for the competition metric (**Macro $F_{0.5}$**), and outputs submission-ready `matching_results.tsv` predictions.

## 🛡️ 3. Training & Validation Strategy (Entity-Grouped Split)

### Preventing Data Leakage
Multiple candidate pairs in the dataset often originate from the same reference entity ($S1$). Splitting candidate pairs at the individual row level causes severe **data leakage** because the model observes features of the entity during training.

The training pipeline in [classifier/train.py](file:///d:/AmazonML/classifier/train.py) uses **`GroupShuffleSplit` grouped strictly by `source1_entity_id`**:
- **Train Set**: 80% of $S1$ entities (and all their associated candidate pairs).
- **Validation Set**: 20% of $S1$ entities (completely unseen during training).

## 🎯 4. Decision Layer & Macro $F_{0.5}$ Threshold Optimization

The challenge metric is **Macro $F_{0.5}$**, which weights **precision twice as heavily as recall**:

$$F_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$

### Singleton Handling in Evaluation
For every $S1$ entity:
- **Ground Truth Empty & Prediction Empty** (Correct Singleton): Score = `1.0`
- **Ground Truth Empty & Prediction Non-Empty** (False Merge): Score = `0.0`
- **Ground Truth Non-Empty & Prediction Empty** (Missed Match): Score = `0.0`
- **General Case**: Standard $F_{0.5}$ score calculated across predicted vs true target sets.

The optimizer in [classifier/threshold.py](file:///d:/AmazonML/classifier/threshold.py) grid-searches decision thresholds from `0.05` to `0.95` with a `0.01` step increment to select the threshold that maximizes validation Macro $F_{0.5}$.

## 🛠️ 6. How to Run Training and Inference

### Training
```bash
python -m classifier.train --features-path data/cache/train_features_sample.parquet
```
- Fits LightGBM model.
- Saves model artifact to `output/classifier_model.joblib`.
- Saves threshold artifact to `output/optimal_threshold.json`.

### Inference
```bash
python -m classifier.predict --features-path data/cache/test_pairwise_features.parquet
```
- Loads model and optimal threshold.
- Scores candidate pairs $P(\text{match})$.
- Formats final submission output into [output/matching_results.tsv](file:///d:/AmazonML/output/matching_results.tsv).
