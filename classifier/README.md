# Classifier Module — Business Entity Resolution

The **Classifier Module** forms Stage 4 of the end-to-end Machine Learning pipeline for the **Amazon ML Challenge 2026: Business Entity Resolution**. 

It receives pairwise candidate records alongside numerical similarity features generated downstream of candidate blocking, fits a high-precision tabular gradient boosting model, optimizes decision thresholds for the competition metric ($F_{0.5}$), and produces final predicted entity matches.

---

---

## 1. What the Classifier Does
- Takes candidate pairs generated by blocking and scored by pairwise feature extraction.
- Trains a scikit-learn compatible tabular gradient boosting model (LightGBM with HistGradientBoosting fallback).
- Evaluates predicted candidate match probabilities against ground truth.
- Performs grid-search threshold optimization to maximize the competition **Macro $F_{0.5}$** metric.
- Generates the final scored `output/matching_results.tsv` file.

---

## 2. Input Expected from the Pairwise Module

The pairwise feature developer will provide a single table (CSV, TSV, or Parquet) containing candidate pairs with entity identifiers and numerical similarity features.

### Expected Input Schema:
| Column | Type | Description |
| :--- | :--- | :--- |
| **`source1_entity_id`** | String | Reference Source 1 entity ID (e.g. `S1-00001`) |
| **`target_entity_id`** | String | Target candidate entity ID (e.g. `S2-00047` or `S3-00812`) |
| **`target_source`** | String | Candidate source label (`S2` or `S3`) |
| **`is_match`** | Integer (0 or 1) | Ground truth match label *(Required for training only)* |
| **`<pairwise_feature_1>`**, **`<pairwise_feature_2>`**, ... | Numeric | Numerical similarity scores (e.g., Jaccard, Levenshtein, embeddings) |

> ⚠️ **IMPORTANT**: The exact pairwise feature names are **intentionally NOT defined** in this module yet. The schema validator dynamically inspects or loads feature column names defined in `config.py`.

## 3. Output Produced

1. **Model Artifact**: `output/classifier_model.joblib` (Trained model + feature metadata).
2. **Threshold Artifact**: `output/optimal_threshold.json` (Best threshold & grid search metrics).
3. **Official Predictions**: `output/matching_results.tsv` (Leaderboard-formatted TSV with `source1_entity_id` and `matched_entity_ids`).

---

## 4. How Training Works

1. **Data Loading**: Loads pairwise candidate features via `load_dataframe()`.
2. **Schema Validation**: Validates presence of `source1_entity_id`, `target_entity_id`, `target_source`, and numerical features using `feature_schema.py`.
3. **Grouped Split**: Performs a **GroupShuffleSplit by `source1_entity_id`** (see Section 5 below).
4. **Model Fitting**: Fits `ClassifierModel` on training fold candidate pairs.
5. **Threshold Optimization**: Grid searches thresholds on the validation fold to maximize Macro $F_{0.5}$.
6. **Persistence**: Saves model weights and optimal threshold to `output/`.

---

## 5. Why Train/Validation Splitting is Done by S1 Entity

In Entity Resolution, multiple candidate pairs often belong to the same reference entity ($S1$). 

- **Incorrect Approach (Row-level Random Split)**: Splitting candidate pairs randomly puts candidate pair A of $S1_1$ into train, and candidate pair B of $S1_1$ into validation. This causes severe **data leakage** because the model sees features of $S1_1$'s name and address during training.
- **Correct Approach (S1 Entity Grouped Split)**: All candidate pairs belonging to a given `source1_entity_id` are placed strictly in either the training set OR the validation set. This mirrors test conditions where the model evaluates completely unseen $S1$ entities (including out-of-distribution entities from France).

---

## 6. How Threshold Optimization Works (`threshold.py`)

1. Scans candidate thresholds from `0.05` to `0.95` with a step of `0.01`.
2. For each threshold $t$:
   - Scores candidate pairs $P(\text{match}) \ge t$.
   - Groups positive predictions by `source1_entity_id`.
   - Computes S1-level Macro $F_{0.5}$ against ground truth using `evaluate.py`.
3. Selects the threshold yielding the highest validation Macro $F_{0.5}$.

---

## 7. How Macro $F_{0.5}$ is Calculated (`evaluate.py`)

Evaluation is strictly performed at the **Source 1 entity level**:

$$F_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$

For every $S1$ entity:
- **Ground Truth Empty & Prediction Empty** (Correct Singleton): Score = `1.0`
- **Ground Truth Empty & Prediction Non-Empty** (False Match): Score = `0.0`
- **Ground Truth Non-Empty & Prediction Empty** (Missed Match): Score = `0.0`
- **General Case**: Calculate $F_{0.5}$ from True Positives, False Positives, and False Negatives.

$$\text{Macro } F_{0.5} = \frac{1}{N} \sum_{i=1}^{N} F_{0.5}(S1_i)$$

## 8. Pairwise Developer Integration Guide

### Step 1: Finalize Pairwise Output File
Save your pairwise feature table to `data/pairwise_features.parquet` (or CSV/TSV) containing:
- `source1_entity_id`
- `target_entity_id`
- `target_source`
- `is_match` (for training set)
- Your numerical similarity columns

### Step 2: Update `config.py`
In `classifier/config.py`, populate `FEATURE_COLUMNS`:
```python
FEATURE_COLUMNS = [
    "name_jaccard_sim",
    "name_levenshtein_sim",
    "address_token_overlap",
    "postal_code_exact_match",
    # Add your feature column names here
]
```

### Step 3: Run Training & Inference
```bash
# Train model & optimize threshold
python -m classifier.train --features-path data/pairwise_features.parquet

# Generate test predictions
python -m classifier.predict --features-path data/test_pairwise_features.parquet
```

```text
├── threshold.py         # Grid-search threshold optimizer for F0.5
├── utils.py             # Generic IO, serialization, and logging helpers
└── README.md            # Module architecture & integration documentation
```
